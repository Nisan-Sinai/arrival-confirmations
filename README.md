# אישורי הגעה

מערכת אישורי הגעה לאירועים — הזמנה דיגיטלית שנשלחת בוואטסאפ, טופס אישור הגעה
לאורחים, ודשבורד ניהול לבעלי השמחה. עברית מלאה, RTL, mobile-first.

בניגוד לשירותי אישורי ההגעה המסחריים, המערכת הזו **חינמית לחלוטין** — היא רצה על
המסלול החינמי של Vercel ושל Supabase, בלי מנוי, בלי תשלום לפי אורח ובלי הגבלה על
מספר ההזמנות.

המערכת אינה קשורה לסוג אירוע מסוים. `config/eventTypes.ts` מגדיר 11 סוגי אירוע —
ברית מילה, זבד הבת, פדיון הבן, חלאקה, בר מצווה, בת מצווה, אירוסין, חינה, חתונה,
יום הולדת ואירוע כללי — וכל אחד מהם מביא איתו את הנוסח והתוויות המתאימים.

המערכת עלתה לאוויר ומשרתת אירוע אמיתי.

  יותר: אובייקט שהמסד מכיר והריפו לא.

צילומי מסך יתווספו כשיהיה seed שאפשר לצלם בלי נתוני אורחים אמיתיים — ראו §17
ב-PLAN.md: אין בתיעוד הזה שום דבר שלא רץ באמת.

## סטאק

Next.js 16 (App Router) · React 19 · TypeScript strict · Tailwind CSS 4 ·
Supabase (Postgres, Auth, RLS, pg_cron) · Server Actions + Zod · Vitest ·
Playwright · axe-core · Stryker · Vercel

הטפסים אינם מבוקרים ומשתמשים ב-`useActionState` מול Server Actions, ולא ב-React
Hook Form: כך הם עובדים גם לפני hydration — אורח על חיבור חלש באולם יכול לענות
לפני שה-JavaScript סיים להיטען. הקומפוננטות ב-`components/ui/` נכתבו לפרויקט לפי
מוסכמות shadcn, אך אינן מותקנות ממנו.

## דו-לשוניות (i18n): עברית ו-English

עברית היא ברירת המחדל ויושבת בשורש; אנגלית היא קידומת `/en` מעל אותם נתיבים. זה לא
קישוט: קישורי `/e/<publicId>` כבר נשלחו לאורחים בוואטסאפ, וסכימה שמעבירה אותם
ל-`/he` הייתה שוברת כל הזמנה שכבר בחוץ.

**מה כבר מתורגם ומוזג ל-main:**

- **המשטח הציבורי** — דף הבית, מחירים, פרטיות, נגישות.
- **ההתחברות** — כניסה, הרשמה, שחזור סיסמה, בחירת סיסמה חדשה ו-`auth/callback`,
  כולל הודעות ה-Server Actions (מודעות-locale).
- **כפתור מעבר שפה** ו-`hreflang` בין שתי הגרסאות.

**מה נשאר עברית בכוונה:** עמודי האורחים `/e/<publicId>` ו-`/invite` והקומפוננטות
שלהם, ותבניות הוואטסאפ ב-`config/messages.ts` — הנמענים דוברי עברית והקישור מוביל
לעמוד עברי.

**מה עוד לא תורגם (הפאזה הבאה):** המשטח המאומת — הדשבורד וכל מסכי הניהול
(`admin/*`), הקומפוננטות הכבדות שלהם וה-Server Actions שלהם. זו עבודה גדולה, ובניית
עץ `/en` מאומת מלא היא נקודת החלטה שכדאי לאשר לפני שמתחילים.

**הדפוס (חובה לעקוב אחריו):**

- כל הקופי במילון המוקלד ב-`config/dictionary/` — טיפוס אחד (`types.ts`) ושני
  מימושים (`he.ts`, `en.ts`). תרגום חסר = שגיאת קומפילציה. `getDictionary(locale)`.
- פרימיטיבים ב-`lib/i18n.ts`: `localePath`, `stripLocale`, `alternateLocale`,
  `languageTag`, `defaultLocale`. קומפוננטות מקבלות פרופ `locale` (ברירת מחדל
  `defaultLocale`) וקוראות `getDictionary(locale)`; כל קישור עובר דרך `localePath`.
- שני root layouts — `app/(he)/layout.tsx` ו-`app/(en)/layout.tsx` — כי רק הפריסה
  החיצונית פולטת `<html>` ו-`lang`/`dir` משתנים לפי השפה. העץ האנגלי יושב תחת
  `app/(en)/en/…`, ו-`app/global-not-found.tsx` נותן 404 עברי לכתובת לא-מותאמת.
- גופי-עמוד משותפים לפי locale; ה-route העברי והאנגלי הם עטיפות דקות מעליהם. תוכן
  משפטי עשיר משתמש במודל ה-runs שב-`features/legal/LegalPage.tsx`.
- Server Actions מודעי-locale: שדה נסתר `locale` בטופס → `getDictionary(locale)`.
  הדוגמה המלאה: `app/actions/auth.ts` יחד עם `features/auth/AuthForm.tsx`.
- `tests/unit/config/dictionary.test.ts` אוכף זהות מבנה he/en, שאין עברית באנגלית,
  ושכל מחרוזת אכן תורגמה (en≠he). ערך ניטרלי-שפה נכנס ל-`LANGUAGE_NEUTRAL`.

## בדיקות ו-CI

השער ב-`.github/workflows/ci.yml` רץ על כל דחיפה ועל כל pull request, ואינו מייעץ:
format, lint, typecheck, כיסוי עם ספים של 100% statements ו-99% branches, build,
קוד מת, סחיפת מיגרציות, סריקת סודות. משרה שנייה מריצה את Playwright ואת axe מול
build אמיתי.

חבילת ה-E2E כותבת למסד אמיתי — היא שולחת טפסים אמיתיים לשרת אמיתי — ולכן היא מוחקת
בסיום בדיוק את השורות שיצרה, לפי מספרי הטלפון שהיא עצמה חילקה. כשלון בניקוי מפיל את
הריצה: ניקוי ששותק כשהוא לא הצליח הוא איך שאורחים בשם "בודק אוטומטי" הצטברו על
הזמנה אמיתית בלי שאיש שם לב.

## אבטחה

מודל האבטחה המלא — מטריצת הגישה למסד, מחזור החיים של טוקן ההזמנה, החלפת הטוקן
לסשן, הרשאות האדמין והגבלת הקצב — מוגדר ב-§4 של [PLAN.md](PLAN.md). איסופו
ל-SECURITY.md נשאר חוב.

כללים שכבר אכופים בקוד:

- `lib/server/env.ts` מוגן בחבילת `server-only`, כך שייבוא שלו מקומפוננטת לקוח הוא
  שגיאת build ולא באג בזמן ריצה.
- `pnpm scan:secrets` נכשל אם ערך סוד אמיתי, JWT עם `role: service_role`, או אפילו
  שם של משתנה סביבה מורשה מופיע בבאנדל של הדפדפן.
- `next.config.ts` שולח כותרות אבטחה בכל תגובה: CSP עם `frame-ancestors 'none'`,
  `object-src 'none'` ו-`base-uri 'self'`, ולצדן `X-Frame-Options`,
  `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` ו-HSTS.
  הן נבדקות ב-`e2e/invitation.spec.ts`.
- `assertNoPlaceholders()` רץ ב-`app/layout.tsx`, כך ש-build לפרודקשן נכשל כל עוד
  ערך תצורה כלשהו עדיין מכיל `__REPLACE_ME__`.
- דפי ההזמנה נושאים `noindex, nofollow` ויושבים מאחורי `Disallow` ב-`robots.txt`.
  זו בקרת גישה ולא העדפת SEO: הזמנה מאונדקסת מבטלת את ה-URL הבלתי-ניחוש.

## הזמנה שנשלחת בוואטסאפ

קישור עירום בקבוצה משפחתית לא נבדל מספאם, וזה בדיוק הרגע שבו אורח מחליט אם ללחוץ.
לכן כל הזמנה מייצרת כרטיס Open Graph משלה — שמות בעלי השמחה, האירוע, התאריך והמקום,
באותו בורדו וזהב של הדף שנפתח אחריו.

הכרטיסים מצוירים ב-Satori, שאין לו גופנים משלו **ואין לו אלגוריתם דו-כיווני**. הוא
מצייר גליפים לפי סדר הזיכרון, משמאל לימין, ולכן עברית שמועברת אליו כמות שהיא יוצאת
הפוכה. `lib/ogText.ts` מסדר כל מחרוזת לפני שהיא מגיעה לרנדרר — פרוסה מדודה מ-UAX #9
— ו-`features/og/OgText.tsx` פורס את המילים כתיבות נפרדות בשורה `row-reverse`, מה
שגורם גם לגלישת השורות להישבר במקום הנכון.

## שמירת נתוני אורחים ומחיקתם

§14 מיושם: `purge_expired_guest_data()` הופכת רשומות RSVP לאנונימיות במקום — בעל
השמחה שומר את ספירת הראשים ומאבד כל מזהה — מוחקת רשומות אורחים, וגוזמת את יומן
הביקורת לפי גיל. pg_cron מריץ אותה כל לילה ב-03:15 UTC, ולא סקריפט שמישהו צריך
לזכור.

לעולם אין להכניס פרטי אורחים אמיתיים ל-seeds, ל-fixtures, לצילומי מסך, ללוגים או
ל-artifacts של CI.
